# Demo: three real tasks for the agent

The agent (Claude Desktop or Cursor) uses only the MCP tools generated by Synapse from the GeoVision Catalog API.
The API code is not changed during the demo. Areas of interest are in `demo/zones/` (approximate polygons).

## Task 1 - clear scenes over a region (POST /catalog/area)

> Find KazEOSat-1 scenes over the Zhambyl region (use the polygon from `demo/zones/zhambyl_region.geojson`)
> acquired in June 2026 with cloud cover below 20 % and an incidence angle below 30°.
> Give me a table: code, date, cloud %, incidence angle, quicklook link. Newest first.

Expected: one call to `POST /catalog/area` with `Cloud=20`, `max_incidence=30`, `only_known=true`.
Check: 7 scenes match (74 intersect the area in June 2026).

## Task 2 - is the data fresh, and what is new over Almaty? (GET /db/status + GET /catalog)

> How fresh is the scene database? Then check the live catalog for scenes over Almaty city
> from 20 to 25 November 2026 and tell me which of them already have a cloud estimate.

Expected: `GET /db/status` (last scene date, number of scenes with cloud cover), then `GET /catalog`
with the Almaty bounding box. The agent should notice that brand-new scenes have `Cloud_Known=false`
and say so instead of inventing a value.

## Task 3 - where to re-shoot? (several calls + aggregation)

> For the West Kazakhstan region, compare October 2026 by week: how many scenes per week,
> how many of them were cloudy (> 50 %), and which week was the worst for imaging.
> Suggest whether we should plan re-acquisition.

Expected: four or five `POST /catalog/area` calls (one per week, `only_known=true`) or one call with
`GET /db/scenes` + grouping, then a short summary with numbers.

## What to show in the recording

1. `Запустить_API.bat` -> `http://127.0.0.1:9100/docs` (the original app, unchanged).

4. Tasks 1-3, with the tool calls visible.
